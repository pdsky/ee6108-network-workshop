# 开始使用这份网络实验样例

本包面向一般工程背景的理工学院学生，使用 Cisco Packet Tracer 9.0.1，教学时间一天七小时。先打开完整样例认识结果，再按学生手册从起始文件练习。`.pkt` 是可操作的模拟网络，手册负责解释、任务和记录；本包是 CA1 实验资源与教学样例，正式提交还须按课程要求整合课件、报告、贡献表及小组和个人视频。

## 先看完整样例

1. 打开 Packet Tracer，选择 **File → Open**，进入本包 `PacketTracer` 文件夹，打开 `04_acl_solution.pkt`。用 **File → Save As** 另存自己的副本。刚打开文件时先等待设备启动与交换机端口进入转发状态，或点击左下角 **Fast Forward Time** 推进模拟时间，再发起测试。
2. 单击 `Student_A`，进入 **Desktop → IP Configuration** 查看地址：IP 为 `10.61.8.10`，掩码 `255.255.255.192`，网关 `10.61.8.1`。这一步先观察，避免随意改动完整样例。
3. 在同一 PC 的 **Desktop → Web Browser** 中输入 `http://10.61.8.100`，点击 **Go** 查看资料服务器页面。必须写对 `http://` 和地址；ping 成功不能代替网页测试。
4. File → Save 保存整个项目。网络设备中的启动配置保存与 `.pkt` 保存是两件事；结束前重开自己的文件，重新测试。

## 发起自己的测试

切到 **Realtime**。在 PDU 列表区新建 **Scenario**，使用 **Add Simple PDU**（信封工具），先点源设备，再点目标设备；它发起一次 ICMP/ping 测试。用设备标签确认对象，查看本次行的 Successful 或 Failed，不把打开文件时已有的旧行当作当前结果。

04 中可比较：Student_A → Student_B、HTTP_Server、Remote 应可达；Student_A → Teacher 应被策略拒绝。首发可能因 ARP 学习尚未完成而失败，等待后重新新建 PDU 并记录复测；仍失败时检查配置与事件，不把全部失败都解释成 ARP。绿色链路只能帮助判断链路状态，不能证明路由、服务或 ACL 正确。

## 看数据怎样走

保存副本，切到 **Simulation**，在 **Edit Filters** 选 ARP、ICMP，或观察网页时选 TCP/HTTP。新建测试，用 **Capture/Forward** 一步一步推进，单击事件或信封，查看 **OSI Model** 和 Inbound/Outbound PDU Details。先看学生到服务器，再看学生到教师在哪一步被拒；只记录界面实际显示的字段。完成后回到 Realtime 复测。

## 按阶段学习

| 文件 | 学习任务 |
|---|---|
| 01_starter.pkt | 已连接 10 个设备、9 条线，仍为默认设备名且未配置地址；对照手册辨认端口并开始配置 |
| 02_vlan_only.pkt | 配置终端、access 与 trunk，解释同 VLAN 跨交换机通信及跨 VLAN 暂不可达 |
| 03_routing_open.pkt | 认识子接口、网关、静态去程和回程路由，建立 HTTP 基准 |
| 04_acl_solution.pkt | 比较同一源、目标和协议加 ACL 前后的变化，解释规则顺序与 in 方向 |
| 05_fault_vlan_access.pkt | 已提供的单故障题：SW_B Fa0/1 错在 VLAN 20；将端口恢复 VLAN 10，再验证两学生通信 |

每阶段先独立预测，再操作、复测和解释；两人轮换操作员与观察员。落后时可打开对应阶段副本继续，但要写明借助了参考文件。个人计算、路径解释和小组文件分别提交，不能用共同配置成功代替每人的学习证据。

## 当前已确认的结果

02 实测学生 A→B 成功、A→教师失败。03 新场景实测 A→教师、A→服务器 ICMP、远端→A 成功；重新新建 A→远端也成功，旧行保留了早期首发 ARP 未完成的失败。03 与 04 均实际显示 HTTP 页面。

04 已导出核对完整 ACL 顺序及学生子接口的 in 绑定；新场景实测 A→教师 Failed，A→B、服务器 ICMP、远端 Successful。重新打开 03，从空白浏览器发起 HTTPS 请求，正确加载了服务器页面；04 的 HTTPS 显示 Request Timeout，HTTP 仍可访问。05 实测 A→B Failed，课堂中需恢复端口并自行验收修复。FTP 尚未实测。最终结果与截图见独立验证日志及 `evidence`，不要把预期表填成自己的测试记录。

## 配置文本与 CRC 扩展

`configs` 中普通 `.txt` 是给相应设备 CLI 逐行输入的命令，出现 Invalid input 应停下核对模式、设备和接口。`.merge.txt` 是纯配置文本，用于设备 **Config → GLOBAL/Settings → Running Config → Merge**，不是给 Windows 执行的脚本。先核对文件名与设备，不反复盲目合并。

Merge 是叠加运行配置，不会自动清空旧条目。把路由开放配置合并到已加 ACL 的设备，不能恢复为没有 ACL 的 03 状态；需要回退时重新打开 03 副本，或明确删除相应配置并复核。保存后重新测试。

`03_CRC检错与重传扩展.md` 提供纸面比特串、XOR 检验和重传活动。它不声称 Packet Tracer 已注入线路比特翻转；ACL 拒绝不是 CRC 差错，手动再次 ping 也不证明 TCP 自动重传。选择这项二十分钟扩展时替换加深练习，总教学时间仍为 420 分钟。
