# 工程体验网络教师指导与六人分工

受众：一般工程背景的理工学院学生。教学净时长：一天 420 分钟。

软件：Cisco Packet Tracer 9.0.1。主线包括 Subnetting、VLAN、VLAN 间路由与静态路由、ACL。CRC 检错与重传作为 20 分钟可选扩展。

本流程配合学生实验手册和分阶段 .pkt 使用。教师专用答案在附录一，正式教师版随后附学生手册全文，便于把指导与操作步骤逐项对应。实际技术通过情况以独立验证日志为准。下文“验收”是教师应在课堂收集的证据，不是已经发生的学生学习效果。

## 一 受众前提与学习价值

学生应能打开软件、保存文件、读简单系统图并进行基本整数运算；不要求预先会 Cisco CLI、子网划分、VLAN、路由表或 ACL。开场摸底检查这些前提，软件操作困难由助手补救。

工程实验中的测量电脑、资料服务器、监控终端和远端设备可能需要跨网络交换信息。本例把它们简化为 PC 和 HTTP 服务器，让学生看到“地址容量、逻辑分组、网络互联、访问边界”怎样一起影响一项工程需求。课堂不执行真实仪器控制。

本课采用引导式实践：完整 CLI 模板供阅读与操作，学生先独立预测，再配置关键部分并用证据解释。一天后可合理要求学生计算本例某个指定子网，配置终端和一个 access 端口，读懂网关与去回路径，比较 ACL 前后结果并诊断一个单故障；不能仅因复制完整配置成功就认定每人能独立规划企业网、设计任意 VLSM 或部署完整安全防火墙。

两人一组共享电脑，分别担任操作员和观察员；在终端配置、第二台交换机和路由阶段轮换。每个人必须实际操作至少一项，并先独立写个人题和迁移计划。六名项目成员是备课与组织团队，不是课堂仅有六名学生。

## 二 固定拓扑与教师应掌握的基准

模型共 10 个节点、9 条连线：R1、R2，SW_A、SW_B、SW_REMOTE，Student_A、Student_B、Teacher、Remote 与 HTTP_Server。R1 与 R2 为 2911，交换机为 2960。CLI 名称采用 R1、R2、SW-A、SW-B 时，画面标签仍可能用下划线；先核对设备窗口和端口，再输入命令。

教学逻辑容量需求设为学生至少 40 个地址、教师至少 20 个、服务器至少 10 个、路由器互联 2 个、远端至少 20 个。屏幕仅放代表性终端，不按十个示例节点推算实际容量。

| 用途 | 网络与前缀 | 有效主机范围 | 广播 | 本例网关或接口 |
|---|---|---|---|---|
| 学生 VLAN 10 | 10.61.8.0/26 | 10.61.8.1–.62 | .63 | R1 G0/0.10：10.61.8.1 |
| 教师 VLAN 20 | 10.61.8.64/27 | 10.61.8.65–.94 | .95 | R1 G0/0.20：10.61.8.65 |
| 服务器 VLAN 30 | 10.61.8.96/28 | 10.61.8.97–.110 | .111 | R1 G0/0.30：10.61.8.97 |
| R1–R2 | 10.61.8.112/30 | .113、.114 | .115 | R1 G0/1 .113；R2 G0/0 .114 |
| 远端 LAN | 10.61.9.0/27 | 10.61.9.1–.30 | .31 | R2 G0/1：10.61.9.1 |

表中前四行省略处均承接 10.61.8。普通子网可用主机数是本例的地址容量，不把 /31 等其他情形混入新手课段。前缀与掩码对应可参考 [IPv4 子网表 RFC 1878](https://www.rfc-editor.org/rfc/rfc1878.html)。

学生终端分别为 10.61.8.10 和 .11，教师为 .70，服务器为 .100，远端为 10.61.9.10。SW_A 的 Fa0/1 是学生 access VLAN 10，Fa0/2 是教师 access VLAN 20，G0/1 连接 R1 G0/0，G0/2 连接 SW_B G0/1；两条主园区上联为 trunk。SW_B Fa0/1 是学生 VLAN 10，Fa0/2 是服务器 VLAN 30。远端交换机使用默认单一 VLAN 1，其上联不是主园区 trunk。

R1 到远端的静态路由为 10.61.9.0/27，经 10.61.8.114；R2 到主园区的汇总回程路由为 10.61.8.0/24，经 10.61.8.113。这个 /24 也覆盖本例未分配的地址，不能解释成这些地址已有主机。

学生 ACL 绑定 R1 G0/0.10 的 in 方向，依次：允许到服务器 .100 的 TCP 80；允许到该服务器的 ICMP；拒绝到该服务器的其他 IP 流量；拒绝到整个教师 /27；允许其他 IP 流量。它不检查不经过 R1 的学生同 VLAN 通信。

**无状态边界必须讲清：**Teacher 主动 ping Student_A 时，学生回复目的仍是教师网络，进入学生子接口时会遇到拒绝规则，完整 ping 因此也可能失败。本策略不能保证教师发起的访问均成功。

## 三 课前准备与阶段文件

1. 在教师机和代表性学生机确认版本、CLI 操作、保存与文件重开。投影须能读清接口、前缀、ACL 顺序和结果表。
2. 分发起始文件与学生任务，将其他阶段文件作为验收后的对照及补救。名称为 01_starter.pkt、02_vlan_only.pkt、03_routing_open.pkt、04_acl_solution.pkt；最终以交付包目录为准。
3. 对照独立验证日志复测各阶段，不使用上次残留的 PDU 状态代替当前测试。HTTP 要真实访问 http://10.61.8.100；ping 成功不能替代网页测试。
4. 准备一个单故障副本并事前试跑，写清引入哪一项、预期影响与恢复方法。不要同时破坏 VLAN、路由与 ACL，也不要把尚未开启服务的失败用作策略证据。
5. 准备个人摸底题、同构后测题、地址计算表、阶段结果表和提示级别记录。纸上回答和软件配置证据分别收集。
6. 准备恢复副本。遇到配置进度落后的组，恢复正确阶段后继续学习解释，不让一个早期命令错误阻断全部后续内容。
7. 如选择 CRC 扩展，发放比特串、XOR 算法和计时卡；软件 FCS/TCP 观察按扩展正文的未实测声明和准备要求执行。

| 阶段 | 教师确认的用途 | 阶段进入条件 |
|---|---|---|
| 01 起始 | 检查设备和端口、另存练习副本 | 学生能找到正确终端与网络设备 |
| 02 VLAN | 同 VLAN 跨交换机的基准 | 同 VLAN 成功，能解释为何跨 VLAN 尚失败 |
| 03 路由开放 | 各既定网络和 HTTP 服务的基准 | 记录网关、去回路由及当前端到端结果 |
| 04 ACL | 在已可用路由上比较策略 | 记录至少一个允许、一个拒绝和一个远端保持可用 |

## 五 每段怎样教 怎样学 怎样验收

### 开场与摸底 30 分钟

教师用“学生取资料、教师配置设备、远端回传数据”介绍需求，再让学生把四种技术分别对应到容量、分组、互联和访问策略。前 8 分钟独立摸底，不记为正式成绩；之后只示范软件入口和一条命令的配置模式，不演示完整答案。

学生另存自己的 01 副本，指出终端、交换机、路由器与两条 trunk。观察员读步骤，操作员执行；教师随机让观察员指出当前配置对象。

证据：个人起点答案和个人文件。补救：助手先帮助找窗口与保存；已经熟悉软件的学生做地址判断，不让熟悉按钮的人代替同伴学习。

### 子网规划与终端配置 75 分钟

| 分钟 | 教师引导 | 学生步骤与证据 |
|---|---|---|
| 0–15 | 用 40 个主机地址说明 /27 的 30 个可用地址不够，示范容量与块边界 | 写出 /26、/27、/28、/30 的容量与末段步长 |
| 15–30 | 只完成学生 /26 的网络、范围与广播示例；其余表作为支架 | 每人独立计算教师 /27 或服务器 /28 的边界，不能只抄参考表 |
| 30–50 | 示范一台终端，再暂停 | 两人分别配置终端，读回 IP、实际掩码与默认网关 |
| 50–65 | 提问 .64、.95、.100 能否当 VLAN 20 主机 | 对三地址写理由；指出 .70 与 .65 为何同网 |
| 65–75 | 核对地址唯一性、容量、文件保存 | 留个人计算与配置证据；需要帮助时记录提示级别 |

要点：网络地址与广播不能作本例主机地址；网关应是本侧路由器有效地址，并非固定 .1。/26 等非 /24 掩码必须实际填写，软件自动推断值可能不符合规划。题目判断来自地址与掩码，不来自 VLAN 数字。

最低进入条件：能计算一个指定网络，至少正确配置一台终端，并说明网关属于本侧网络。慢组获得其余网络参考表，不要求短时间独立重算全表。

### VLAN 与 trunk 75 分钟

教师先问 Student_A 与 Student_B 接在不同交换机，为何仍可能属于同一组；让学生区分物理位置、IP 子网和 VLAN。展示一个 access 端口，再让另一名学生配置对应端口；trunk 使用模板，但每组要指出其两端和允许的 10、20、30。

学生按指南配置 SW_A、SW_B，运行 show vlan brief 与 show interfaces trunk。逐项核对 access 归属，再观察 trunk 输出；trunk 不出现在某 VLAN 的 access 端口栏，不等于它失效。

学生先预测 Student_A→Student_B，再发当前测试，初测失败时等待并核对配置。随后预测跨 VLAN，解释此阶段未提供完整三层互联。教师巡视时问“改 IP 是否会自动改变 VLAN”，标准答案是否。

证据：一个 access 端口的配置/显示、trunk 输出、同 VLAN 跨交换机结果及一句解释。15 分钟用于示范、30 分钟配置、20 分钟预测/测试/仿真、10 分钟验收与补救。慢组用 02 对照并重新完成一个关键端口；快组查一条 trunk 携带 VLAN 的条件，不临时增加复杂 STP 任务。

### VLAN 间与静态路由 90 分钟

| 分钟 | 教师引导 | 学生步骤与证据 |
|---|---|---|
| 0–15 | 画学生→服务器与学生→远端路径，先问何处需要路由 | 标出本侧网关、VLAN 入口、R1/R2 去回方向 |
| 15–40 | 示范一个 R1 子接口的 dot1Q 与地址；其余用模板 | 每人识别或配置一个子接口，核对 VLAN 标签，不只看 .10 后缀 |
| 40–55 | 示范 /30 互联与一条静态路由 | 核对 .113/.114，填写另一方向目的网络与下一跳 |
| 55–75 | 先测网关，再测园区与远端，最后浏览 HTTP | 记录当前结果；运行接口和路由表显示 |
| 75–90 | 单步看一条跨 VLAN/远端路径，提问回程缺失后为何失败 | 保留路由和 HTTP 基准，保存 03 副本 |

R1 G0/0 物理接口保持开启，网关在三个子接口；dot1Q 指定 VLAN，后缀是选择的命名。配置与技术背景可参照 [Cisco 802.1Q VLAN 间路由资料](https://www.cisco.com/en/US/docs/ios/lanswitch/configuration/guide/lsw_cfg_vlan_encap.html)。

最低进入 ACL 的条件：课堂基准中的 Student_A→Teacher、服务器 ICMP/HTTP 与远端通信已经在当前文件验证。未通过组恢复 03 并说明路径，避免把原有路由/服务错误误认为 ACL 拒绝。去程成功不能替代回程解释，HTTP 页面也不能证明性能或其他服务可用。

### ACL 策略与比较 75 分钟

1. 前 15 分钟先发策略表而不是命令，让学生预测学生到服务器 HTTP、服务器 ICMP、教师与远端的结果。每人解释一项。
2. 接着 15 分钟展示规则顺序、wildcard、服务器 host 与 TCP 80，逐包跟踪哪条首次匹配。特别比较“服务器其他 IP 拒绝”与最后 permit：删除前者会改变服务边界。
3. 20 分钟用于导入/配置 ACL、绑定 R1 G0/0.10 in 并核对输出。学生指出 in 是以路由器接口为参照，不是“进入目标电脑”。未绑定的规则不构成生效策略。
4. 15 分钟复测与 03 完全相同的源、目的、协议，包含一个允许、一个拒绝和一个远端维持可用。HTTP 继续实际浏览；FTP 仅在教师已启用、配置账号并证明 03 可用时作为选做对照。
5. 最后 10 分钟讨论 Teacher→Student_A 的返回包，并用 Simulation 看拒绝位置或读规则。让学生解释请求与回复的源/目的交换，纠正“教师主动就一定能成功”的误解。

证据：个人预测、03/04 同项对照、规则顺序与绑定方向、返回方向解释。隐含拒绝与首次匹配规则可参照 [Cisco IP ACL 资料](https://www.cisco.com/c/en/us/support/docs/security/ios-firewall/23602-confaccesslists.html)。ACL 控制本例路径的包，不等于完整安全机制，更不是差错纠正。

## 六 最后 75 分钟与 CRC 选择

核心学习与个人评价先完成，CRC 从后 20 分钟的加深任务中替换，不能使当天变为 440 分钟。

| 相对分钟 | 必做或选择 | 内容与证据 |
|---|---|---|
| 0–5 | 必做 | 发一项单故障与诊断规则，先写现象预测 |
| 5–20 | 必做 | 检查、只改一项、复测，留下故障记录 |
| 20–40 | 必做 | 每人独立做迁移计划，再合并与核对；软件变化按能力与时间完成 |
| 40–48 | 必做 | 个人同构后测，不与同伴商量 |
| 48–55 | 必做 | 保存、重新验证指定结果、收集记录并简短分享 |
| 55–75 | 二选一 | CRC 20 分钟扩展；或更多路径/ACL 对比和针对性补救 |

可选 CRC 采用同包《差错控制扩展》：手算 CRC、翻一位检验余数、纸上停等重传，再比较检错、重传和 FEC。原生 GUI 的 bit flip 注入未被官方帮助确认，新增 FCS/TCP 观察与重传操作未实测；只有课前验证并留证的软件场景才用于演示。选做与否不影响主线验收，未完成核心任务的组优先补救。

迁移任务使用新地址块 10.62.8.0/24，每人负责规划一个逻辑区，先选满足同类容量需求的前缀、有效主机与网关，写网络、可用范围和广播；两人核对边界后合并。教师追问“网关换成另一个有效地址要同步改什么”“新学生网络改变后 ACL 哪个源地址范围需更新”。不提供完整地址答案表。

20 分钟内不要求新手重新独立配置整套设备。个人计划证明个人理解，共同软件成果证明小组实施；文件中未完成的部分要写明，不能将预期填写为测试成功。若做软件迁移，另存副本并核对终端、子接口、静态汇总范围和 ACL 地址匹配是否仍一致，不只替换 PC 地址。

## 七 单故障引导与提示记录

课堂可使用已保存的 05_fault_vlan_access.pkt 副本，每组先做一题。其他故障由教师在正常副本中只修改一项并事前验证，更多题仅给进度快的组。

| 故障来源 | 教师引入的单一变化 | 学生必须调查的证据 |
|---|---|---|
| 05 VLAN 故障 | SW_B Fa0/1 的 access VLAN 由 10 改为 20 | 已实测 Student_A→Student_B Failed；核对端口与终端地址，修复后另行复测 |
| 03 路由 | 移除 R2 到 10.61.8.0/24 的回程路由 | 远端端到端变化；R1/R2 路由表与回复路径 |
| 04 ACL | 移除学生入口的 ACL 绑定 | 原拒绝测试是否变为允许；规则仍存在但绑定缺失 |

05 的唯一故障是端口 VLAN 改动，Student_B 仍为 10.61.8.11/26。恢复 VLAN 10 后的结果尚未实测，须学生新建 PDU 自行验收；回程路由与 ACL 绑定故障仍仅为设计。错误掩码可能涉及代理 ARP，不作为未经验证的必失败题。

提示按四档记录：0 无提示；1 一般追问；2 指出检查范围；3 示范定位或直接帮助。一级问“哪项仍可用，它排除了什么”；二级提示检查 VLAN、回程或 ACL 绑定某一类别；三级只示范检查方法，让学生完成修改和复测。允许求助，但个人题先独立完成，不把获得帮助后的成功记为无帮助独立完成。

## 八 个人检查与学习效果证据

前后测使用相同概念、不同数值的三类题，后测每人独立完成。

| 构念 | 课前例 | 课后平行例 | 评价要点 |
|---|---|---|---|
| 容量与有效地址 | 40 个地址能否用 /27；给一个 /27 判断网络/广播 | 20 个地址能否用 /28；给另一 /27 判断边界 | 容量理由与边界，不只背掩码 |
| VLAN 与去回路由 | 不同交换机上同组终端能否通信；跨网由谁转发 | 同 VLAN 与跨 VLAN 各需哪些条件；为何只配去程不够 | 区分二层分组和三层路径 |
| ACL 与会话回复 | 允许/拒绝在什么路径上判断 | permit 放第一条会怎样；教师 ping 的回复为何受影响 | 首次匹配、接口方向、无状态 |

这是工作坊内的评价，不是 CA1 官方评分。学习验收同时看：个人地址计算和迁移计划、实际关键操作、当前阶段测试、路径与策略解释、单故障记录和提示依赖。小组成功与个人题分别报告。

可用四种反馈：已独立达成；一般提示后达成；定位帮助后达成；尚未达成并写出困难。不要仅给“完成/未完成”或满意度作为理解证据，也不要用一个 .pkt 的正确配置推断所有学生都掌握了全部主题。

## 附录一 教师专用参考答案

本附录对应学生手册的十二道个人思考题、阶段一独立 VLSM 计算及 CRC 扩展出口题。答案是按当前拓扑和配置推导的解释标准；测试结果仍由实际运行证明。先收学生个人答案，再讨论或展示本附录，不把抄参考答案记为独立掌握。

### 题 1 容量与前缀

学生题目：VLAN 10 为什么使用 /26？若需要 40 个主机地址，/27 是否够用？写出理由。

参考答案：本例按普通 IPv4 子网计算，可用主机数为 2 的主机位数次方减 2。/27 有 5 个主机位，2^5 - 2 = 30，不足 40；/26 有 6 个主机位，2^6 - 2 = 62，足够。因此在本例候选中选择 /26。若 40 台终端还需另占一个网关地址，总需求 41 也仍在 62 以内。屏幕中只有两台代表性学生 PC，不代表容量要求只有两个。

评价：必须有容量计算和需求比较；只写“地址表规定 /26”不足以证明理解。

### 题 2 地址是否属于教师子网

学生题目：10.61.8.64、10.61.8.95、10.61.8.100 能否分配给 VLAN 20 主机？分别说明。

参考答案：VLAN 20 为 10.61.8.64/27，范围 .64-.95，可用主机 .65-.94。.64 是网络地址，不能分配给本例主机；.95 是广播地址，也不能；.100 超出教师子网，属于本例服务器 10.61.8.96/28，不能用作 VLAN 20 的有效主机地址。不能只看地址前三段相同。

评价：三项分别指出网络、广播、子网不符三种理由；“都不能”但没有理由只是部分理解。

### 题 3 路由器互联的两个地址

学生题目：为什么 10.61.8.112/30 只提供两个可用地址？本例分给哪两个接口？

参考答案：/30 留 2 个主机位，共 4 个地址：.112 网络、.113 和 .114 主机、.115 广播，所以本例有 2 个可用地址。R1 G0/1 用 10.61.8.113；R2 G0/0 用 10.61.8.114。掩码为 255.255.255.252。本题使用普通 /30，不把其他点到点寻址方式混入答案。

评价：指出四地址的角色以及两端接口；不能把 .112 或 .115 用作本例接口地址。

### 题 4 错误掩码改变主机判断

学生题目：如果把 Student_A 的掩码错误设成 /24，哪些目标会被它误当成同网？不要在未实测时断言具体通信一定失败。

参考答案：Student_A 原为 10.61.8.10/26，其本地范围是 .0-.63。误设 /24 后，它把整个 10.61.8.0-.255 视作本地，包括 Teacher .70、HTTP_Server .100 以及路由器互联 .113/.114，虽然这些目标并不在学生 VLAN。Student_B .11 原本就在同网；Remote 10.61.9.10 仍被判为远端。

它会尝试在学生 VLAN 中对误判为本地的目标进行 ARP，而不是按原规划交给默认网关。掩码变化不会自动改变交换机端口所属 VLAN。实际是否可达还可能受代理 ARP 等设备行为影响，应观察本版本的事件和输出，不能只凭纸面判断填写“必定失败”。

评价：区分主机的地址判断与交换机的 VLAN，指出 ARP/网关选择的变化；实际结果以当前测试为准。

### 题 5 网关不必固定为首个地址

学生题目：给 VLAN 30 选择另一个有效网关，需要同步修改哪些设置？网关必须是 .97 吗？

参考答案：不必须为 .97。可选未被占用的有效地址，例如 10.61.8.98/28。将 R1 G0/0.30 的地址改成 .98，并把 HTTP_Server 及其他 VLAN 30 主机的默认网关同步改成 .98；保留正确掩码和 dot1Q 30，确认地址不重复，更新记录并复测。只改主机网关而未改变实际路由器接口不能成立。

若仅在原 10.61.8.96/28 内更换网关，而服务器仍为 .100，则 VLAN ID、trunk、R2 的 /24 回程汇总及 ACL 对服务器 .100 的匹配无需因这一次变更而修改。若连子网或服务器地址也改变，相关路由与 ACL 必须重新核对。

评价：说明地址有效、唯一、对应真实接口且两端同步；不是机械地把所有配置都改一遍。

### 题 6 同 VLAN 跨交换机

学生题目：Student_A 与 Student_B 接在不同交换机，为什么仍可不用路由器通信？需要哪些端口条件？

参考答案：两个终端的 IP/掩码把对方判为同一子网，且接入端口都属于 VLAN 10。同 VLAN 是同一二层广播域，可以经 SW_A 与 SW_B 交换，不必经过路由器；本例学生入口的三层 ACL 也不在这条路径上。

条件包括：SW_A、SW_B 建立 VLAN 10，学生 access 端口归属正确；互联的 SW_A G0/2 与 SW_B G0/1 是正常 trunk 并允许 VLAN 10；链路和端口处于可转发状态；两台 PC 的地址、掩码正确且不重复。默认网关是跨网转发的入口，不能修复错误的 access VLAN 或缺失的 trunk VLAN。

评价：把端口条件与主机条件都说清；“因为都叫学生”或“因为都是 VLAN 10 地址”不足以说明配置机制。

### 题 7 子接口与 VLAN 标签

学生题目：VLAN 20 为什么需要 G0/0.20，而不是只给 R1 G0/0 设置一个地址？子接口后缀与 VLAN 标签是否同一概念？

参考答案：本例一条 SW_A-R1 trunk 承载三个 VLAN，需要给每个 VLAN 提供对应的三层网关。本例在 G0/0 下分别建立子接口，VLAN 20 的子接口地址为 10.61.8.65/27，并用 `encapsulation dot1Q 20` 指定标签。只给物理 G0/0 一个地址，不等于已经为本例三个带标签 VLAN 配好了网关。

`.20` 是所选的子接口编号，dot1Q 20 才是 VLAN 绑定；二者通常选成一致方便阅读，但不是同一字段。物理接口仍须开启，子接口的标签、IP 和掩码也须正确。

评价：能指出物理接口、逻辑子接口、VLAN 标签与网关地址的不同作用。

### 题 8 去程与回程

学生题目：删掉 R2 回程路由后，为什么 R1 的去程路由不够？请画出回复路径。

参考答案：以 Student_A ping Remote 为例，去程仍可按 Student_A → SW_A → R1 → R2 → SW_REMOTE → Remote 发送；R1 的远端静态路由只解决去程。回复走 Remote → SW_REMOTE → R2 → R1 → SW_A → Student_A，R2 必须知道如何到达目标 10.61.8.10。

在本例没有其他替代路由时，删掉 R2 的 10.61.8.0/24 经 10.61.8.113 的回程路由，R2 的直连 10.61.8.112/30 并不包含 .10，无法把回复送回学生子网。端到端 ping 因而不能完成。路由器逐跳对每个包查表，不会因请求来过就自动建立回程静态路由。

评价：完整画出回复方向，指出缺的是 R2 到主园区的路径；实际故障副本须课前验证，不能把本解释当成已实测记录。

### 题 9 ACL 首次匹配与服务边界

学生题目：将 `permit ip any any` 放到 ACL 第一行，后面的拒绝规则会怎样？如果删去服务器的其他流量拒绝，策略会怎样变化？

参考答案：放到第一行后，经过这份 ACL 的 IP 包先匹配许可，后面针对服务器或教师的拒绝不再决定这些包的行为，原设计的访问边界被破坏。这不代表它消除了连线、VLAN、路由或服务故障。

只删第三条服务器其他 IP 流量的拒绝时，HTTP/ICMP 原有许可保留；学生到服务器的其他 IP 流量既不匹配教师子网拒绝，又可匹配末尾 `permit ip any any`，因此也会获准。软件服务是否真的可访问还取决于是否已启用及其他配置；只有先证明 03 阶段服务可用，再比较 04，才能说明 ACL 的影响。

评价：明确逐条首次匹配以及第三条为何在末尾许可前必要；不能说“后面 deny 优先级更高”。

### 题 10 教师请求与学生回复

学生题目：Teacher 发起 ping Student_A 也可能失败，为什么这不能直接证明教师的请求被拒绝？

参考答案：本例 ACL 只绑定学生子接口 G0/0.10 的 in 方向。教师请求从 G0/0.20 进入，再从 G0/0.10 发往学生，不在这份 ACL 的该入口方向检查。配置正常时，请求可到达学生。

学生回复则从 VLAN 10 进入 G0/0.10，源是 10.61.8.10、目标是教师 10.61.8.70，匹配“学生子网到教师子网”的拒绝。完整 ping 因收不到回复而失败。它是逐包、无状态规则，不自动区分谁先发起。应观察请求与回复的实际事件；若软件显示匹配计数也可辅助核对，不能凭最终 Failed 推断丢弃发生在请求端。

评价：交换请求/回复的源目标，区分接口 in/out，避免把本例当成自动放行会话回复的防火墙。

### 题 11 ICMP 成功不代表 HTTP 可用

学生题目：Student_A 与服务器 ping 成功而网页打不开，下一步应核对什么？

参考答案：先确认学生 Web Browser 使用 `http://10.61.8.100`，服务器 Services → HTTP 为 On，端口/协议确为本例 HTTP TCP 80；使用 IP URL 时无需先归因于 DNS。核对实际服务器地址、终端掩码和网关，以及 ACL 是否按正确顺序允许学生到该 host 的 TCP 目的端口 80、是否绑定正确接口方向。

再在 03 路由开放副本用相同 URL 比较：03 也不能打开时先查服务或应用路径；03 可用而 04 不可用时核对 ACL 与实际 TCP 事件。ping 只测试 ICMP，不能证明 TCP 连接、HTTP 服务和网页响应均正常。不随意增加“已访问成功”的记录。

评价：优先检查应用与协议相关条件，使用同源同目标的前后对照，不把一种协议成功推广到全部服务。

| 容量与边界 | 40 个地址可否用 /27？不可，30 不足 40。10.61.8.64/27 的 .70 有效，.95 为广播 | 20 个地址可否用 /28？不可，14 不足 20。10.62.8.128/27 的 .140 有效，.159 为广播 |
| 二层与三层 | 同组 PC 接不同交换机一定需要 router 吗？不一定，同 VLAN/同子网且链路可转发时交换即可；跨 VLAN 需三层网关 | 同 VLAN 跨交换机需 access VLAN 与 trunk 条件；跨 VLAN/远端还需网关和去回路由。只配去程不能保证回复可返回 |
| 规则与回复 | ACL 应结合所经路径与绑定方向逐包判断，完整 ping 包含请求和回复，不能只看发起者 | 第一条 permit any 使后续 IP deny 无法决定这些包；教师 ping 的学生回复进入学生接口，可能被拒，见题 9、10 |

记录个人前后答案、实际操作和提示程度；学习提升只有真实前后证据齐全时才能汇总。不得把教师预写答案或项目作者成功配置当成学生后测结果。

### CRC 扩展出口题

学生题目：CRC 检错与重新发送数据分别解决什么问题？

参考答案：CRC 用冗余校验判断收到的数据是否通过一致性检查；检出差错不等于恢复原比特。确认与超时重传是在未得到所需确认时再发送副本，用额外传输争取正确到达；ACK/重传不属于 FEC。ACL 策略丢包不是载荷比特翻转，手动重发 ping 也不证明 TCP 自动重传。CRC 算式与比特串答案详见同包扩展正文，软件事件只记录实际观察到的内容。

## 场景和四类技术各解决什么

学校工程体验实验室有学生终端、教师终端、实验资料 HTTP 服务器和一个远端实验区。学生终端跨两台交换机，仍属于同一组；学生可访问资料服务器的 HTTP 与 ICMP，可与远端实验区通信，但不应访问教师子网。教师和远端终端保留其他既定通信。

| 技术 | 本项目的作用 | 需要解释的证据 |
|---|---|---|
| IP subnetting | 给不同规模的网络分配不同掩码，检查地址是否有效、是否重叠 | 网络地址、可用范围、广播地址与主机数 |
| VLAN | 在交换机上区分学生、教师和服务器；让两个交换机上的学生属于同一组 | access 端口归属、trunk 可携带的 VLAN、同 VLAN 跨交换机测试 |
| Routing | 路由器让不同 VLAN 和远端子网通信 | 子接口、各默认网关、去程和回程路由 |
| ACL | 在路由已能通信的基础上实施具体访问策略 | 同一项测试加 ACL 前后变化、规则顺序、接口和方向 |

终端只是工程联网设备的模型；本样例不执行真实仪器控制。HTTP 成功也不能证明应用性能、可靠性或整个网络安全。

## 阶段二 VLAN 间与远端路由

从自己的 02 副本继续，或打开教师发放的 02_vlan_only.pkt 后另存。操作员配置时，观察员在拓扑上标出三个网关与 R1/R2 的去程、回程。初学者可由教师引导配置子接口，再各自读回一项设置并独立解释用途。

R1 的 G0/0 是承载多个 VLAN 的物理接口，不给它配置主机网关 IP；网关分别配置到子接口。子接口编号 `.10` 是我们选择的名称后缀，真正的 VLAN 对应由 `encapsulation dot1Q 10` 指定。Cisco 的配置资料使用子接口与 802.1Q 绑定实现 VLAN 间路由。[Cisco VLAN 间路由配置](https://www.cisco.com/en/US/docs/ios/lanswitch/configuration/guide/lsw_cfg_vlan_encap.html)

R1：

```text
enable
configure terminal
hostname R1
interface gigabitEthernet0/0
 no ip address
 no shutdown
exit
interface gigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 10.61.8.1 255.255.255.192
exit
interface gigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 10.61.8.65 255.255.255.224
exit
interface gigabitEthernet0/0.30
 encapsulation dot1Q 30
 ip address 10.61.8.97 255.255.255.240
exit
interface gigabitEthernet0/1
 ip address 10.61.8.113 255.255.255.252
 no shutdown
exit
ip route 10.61.9.0 255.255.255.224 10.61.8.114
end
copy running-config startup-config
```

R2：

```text
enable
configure terminal
hostname R2
interface gigabitEthernet0/0
 ip address 10.61.8.114 255.255.255.252
 no shutdown
exit
interface gigabitEthernet0/1
 ip address 10.61.9.1 255.255.255.224
 no shutdown
exit
ip route 10.61.8.0 255.255.255.0 10.61.8.113
end
copy running-config startup-config
```

R2 的 /24 回程路由覆盖本例主园区已分配的几个子网，同时也覆盖尚未分配的地址。它是本项目的汇总选择，不代表所有 /24 中的地址都已有设备。R1 去远端需要知道下一跳 R2，R2 回复主园区同样需要回程路径。只配去程可能出现请求抵达、回复不能返回的现象。

在两台路由器特权模式检查：

```text
show ip interface brief
show ip route
```

先测试终端到各自网关，再测试 Student_A → Teacher、Student_A → HTTP_Server、Student_A → Remote、Remote → Teacher。成功后保存为自己的 03 阶段副本。地址错误、trunk 未携带 VLAN、物理接口未启用、静态路由缺失是不同问题，不能一次改掉所有设置而不留下原因。

HTTP 另测：Student_A → Desktop → Web Browser，在 URL 填 `http://10.61.8.100`，点击 Go；记录是否看到服务器页面。ping 成功只支持 ICMP 可达，不代替这个应用测试。

## 阶段三 加入学生访问策略

从自己的路由开放副本或 03_routing_open.pkt 开始，先另存为自己的 ACL 阶段文件。已经打开 04_acl_solution.pkt 的同学可直接检查并测试现有规则，不必重复追加同一份 ACL。

本策略使用命名扩展 ACL `STUDENT_POLICY`，绑定在 R1 G0/0.10 的 **in** 方向，含义是检查从学生 VLAN 进入 R1 的 IP 包。它不控制无需经过 R1 的 Student_A ↔ Student_B 同 VLAN 通信。

| 规则顺序 | 行为 |
|---|---|
| 1 | 允许学生子网到 HTTP_Server 的 TCP 目的端口 80 |
| 2 | 允许学生子网到 HTTP_Server 的 ICMP，包含 ping |
| 3 | 拒绝学生子网到 HTTP_Server 的其他 IP 流量 |
| 4 | 拒绝学生子网到整个教师子网 |
| 5 | 放行其余 IP 流量，包含既定远端通信 |

这里允许的是 ICMP，不是只限定一个 ICMP 类型。第三条是必要的服务边界：如果删掉第三条，最后的 `permit ip any any` 也会放行学生到服务器的其他 IP 流量。ACL 逐条匹配，首次匹配后决定行为；未匹配的流量还有隐含拒绝。规则写好却未绑定到接口时不生效。[Cisco IP ACL 配置与处理规则](https://www.cisco.com/c/en/us/support/docs/security/ios-firewall/23602-confaccesslists.html)

在 R1 输入：

```text
enable
configure terminal
ip access-list extended STUDENT_POLICY
 permit tcp 10.61.8.0 0.0.0.63 host 10.61.8.100 eq 80
 permit icmp 10.61.8.0 0.0.0.63 host 10.61.8.100
 deny ip 10.61.8.0 0.0.0.63 host 10.61.8.100
 deny ip 10.61.8.0 0.0.0.63 10.61.8.64 0.0.0.31
 permit ip any any
exit
interface gigabitEthernet0/0.10
 ip access-group STUDENT_POLICY in
end
copy running-config startup-config
```

在 R1 检查：

```text
show access-lists
show ip interface gigabitEthernet0/0.10
```

核对 ACL 顺序、绑定名称、inbound 方向。条件允许时比较测试前后的匹配计数；Packet Tracer 版本与场景可能影响计数显示，以实际输出记录，不填写虚构的计数。

**无状态边界：**这不是会自动识别会话的防火墙。Teacher 主动 ping Student_A 时，请求可发往学生，但学生回复的源仍属于学生子网、目的属于教师子网；回复进入 R1 G0/0.10 时可被第四条拒绝。因此不能声称“教师可以任意访问学生，只限制学生主动访问教师”。若要这样的会话政策，需要另行设计与验证，不在本例中自动成立。

个人练习：先预测 Student_A → Teacher 与 Student_A → HTTP_Server 的 ICMP/HTTP 结果，再执行测试；每人选择一条规则，写出源、目标、协议和方向。教师问你为何失败时，指出配置与事件证据。保存自己的 04 阶段副本，并保留未加 ACL 的 03 文件用于对照。

## 每个阶段的测试预期

表中是设计预期，实际文件验收结果见独立验证日志。学生在自己的副本中建立当前测试，按实际输出填写下面的空白表。跨网络测试用当前地址新建 PDU 或重新发送，不沿用上次地址的历史结果。初次 ICMP 失败可能涉及 ARP 学习；等待并复测，同时查看配置与事件，不能把所有失败都解释成 ARP。

| 源与目标 | VLAN 阶段 02 | 路由开放 03 | ACL 阶段 04 | 解释重点 |
|---|---|---|---|---|
| Student_A → Student_B，ICMP | 预计成功 | 预计成功 | 预计成功 | 同 VLAN 跨交换机，trunk 正常即可，不经过三层 ACL |
| Student_A / Student_B → Teacher，ICMP | 预计失败 | 预计成功 | 预计拒绝 | 先区别路由尚未建立与 ACL 有意拒绝 |
| Student_A → HTTP_Server，ICMP | 预计失败 | 预计成功 | 预计成功 | 对服务器 ICMP 的许可规则 |
| Student_A → HTTP_Server，HTTP | 预计失败 | 预计页面可用 | 预计页面可用 | HTTP 服务需先启用，真实浏览验证 |
| Teacher → HTTP_Server，ICMP 或 HTTP | 预计失败 | 预计成功 | 预计成功 | 教师请求不从学生入口进入 R1 |
| Student_A → Remote，ICMP | 预计失败 | 预计成功 | 预计成功 | VLAN 路由加双向静态路由；ACL 其余许可 |
| Remote → Student_A，ICMP | 预计失败 | 预计成功 | 预计成功 | 学生回复的目的为远端，仍可匹配许可 |
| Remote → Teacher，ICMP | 预计失败 | 预计成功 | 预计成功 | 远端保持互通 |
| Teacher → Student_A，完整 ping | 预计失败 | 预计成功 | 回复可能被拒，完整测试预计失败 | 包过滤也会影响会话回复 |
| Student_A → HTTP_Server，FTP，可选 | 预计失败 | 先证明服务与账号可用 | 预计 TCP 连接被拒 | 只在教师开启 FTP、设置账号并先测 03 后使用 |

FTP 可选测试在学生 PC 的 Desktop → Command Prompt 内使用 `ftp 10.61.8.100`，账号由教师提供。03 的 FTP 登录因账号错误而失败时，不能直接跳到 04 并说拒绝来自 ACL。以上 CLI 与测试均在模拟终端内执行。

## 仿真演示与排错顺序

1. 保存当前工作副本，切换 Simulation，用 Edit Filters 选择本次要观察的 ARP、ICMP，或 HTTP/TCP。
2. 创建新的 Scenario 和测试，使用 Capture/Forward 逐步看 Student_A → HTTP_Server 的设备路径；打开相应 PDU Information 比较经过交换机与路由器时的封装。只记录界面实际显示的字段。
3. 再看 Student_A → Teacher，在 R1 检查有意拒绝发生的位置。不能因为接口仍绿色就判断 ACL 无效。
4. 回到 Realtime，建立当前测试复核，保存项目与自己的解释。

遇到非预期失败，按以下顺序逐项核对：连线端口与接口状态；端口 VLAN 与 trunk；终端 IP/掩码/网关；R1 子接口的 dot1Q 与地址；R1/R2 去程和回程路由；HTTP 服务；ACL 的规则顺序、名称、绑定方向。ACL 阶段先打开 03 对照：若 03 同样失败，优先修复路由或服务，尚不能归因于 ACL。

## 一天七小时怎样安排

这是完整技术演示样例。对网络初学者，优先让他们算清子网、配置一个终端、识别 VLAN 与网关、比较访问策略，而不是要求独立重写所有设备配置。课前摸底显示已有较好网络基础时，可以增加独立命令操作。

|---|---:|---|---|
| 开场与基础摸底 | 30 | 判断已有概念，确认软件操作 | 解释四个主题的关系 |

### 差错控制的二十分钟扩展

教师可安排另文《差错控制扩展 CRC 检错与重传的基本区别》的 20 分钟活动。若纳入同一天，需替换原课段中 20 分钟的重复命令演示或拓展操作，使教学总时间仍为 420 分钟；个人地址计算、核心前后测试和理解检查保留。

扩展先认识帧与 FCS，再用简化比特串独立核验 CRC 余数，并区分检错、重传和前向纠错。CRC 计算按另文的教学模型完成，不把它写成 Packet Tracer 已真实注入线路误码。ACL 的策略拒绝不是 CRC 差错；手动重发 ping 不等于 TCP 自动重传。若教师演示 TCP 确认或重传，必须使用已事先试跑的场景，并记录实际事件。完成后写一句解释：CRC 检错与重新发送数据分别解决什么问题？

## 个人思考题与术语

先独立作答，再讨论。教师可据这些题目区分按表配置与理解规则。

1. VLAN 10 为什么使用 /26？若需要 40 个主机地址，/27 是否够用？写出理由。
2. 10.61.8.64、10.61.8.95、10.61.8.100 能否分配给 VLAN 20 主机？分别说明。
3. 为什么 10.61.8.112/30 只提供两个可用地址？本例分给哪两个接口？
4. 如果把 Student_A 的掩码错误设成 /24，哪些目标会被它误当成同网？不要在未实测时断言具体通信一定失败。
5. 给 VLAN 30 选择另一个有效网关，需要同步修改哪些设置？网关必须是 .97 吗？
6. Student_A 与 Student_B 接在不同交换机，为什么仍可不用路由器通信？需要哪些端口条件？
7. VLAN 20 为什么需要 G0/0.20，而不是只给 R1 G0/0 设置一个地址？子接口后缀与 VLAN 标签是否同一概念？
8. 删掉 R2 回程路由后，为什么 R1 的去程路由不够？请画出回复路径。
9. 将 `permit ip any any` 放到 ACL 第一行，后面的拒绝规则会怎样？如果删去服务器的其他流量拒绝，策略会怎样变化？
10. Teacher 发起 ping Student_A 也可能失败，为什么这不能直接证明教师的请求被拒绝？
11. Student_A 与服务器 ping 成功而网页打不开，下一步应核对什么？
12. 给另一个同规模实验室选择一组不重叠子网，并标出每组的可用范围与网关。先留下个人计划，再在副本配置，不把共同项目成功当作个人题目答案。

| 术语 | 在本例中怎样理解 |
|---|---|
| Prefix / 子网掩码 | 地址中网络位的长度，决定地址范围，不只是格式字段 |
| VLSM | 同一地址块按需求使用不同长度掩码 |
| access 端口 | 连接本例终端，属于指定 VLAN |
| trunk | 在一条交换机或交换机到路由器链路上携带多个 VLAN |
| 802.1Q / dot1Q | VLAN 标签与本例子接口关联的方法 |
| 子接口 | 一个物理接口下的逻辑三层接口，本例分别作为三个 VLAN 的网关 |
| 静态路由 | 手动指定目标网络、掩码和下一跳；回复也需要路径 |
| ACL wildcard | 匹配地址时的通配掩码；本例 /26 对应 0.0.0.63，/27 对应 0.0.0.31，不是子网掩码本身 |
| in / out | 以绑定的路由器接口为参照，进入或离开路由器的包方向 |
| 隐含拒绝 | ACL 没有匹配任何规则时的默认拒绝 |
| 无状态 | 本例规则逐包判断，不自动记住谁先建立了会话 |
