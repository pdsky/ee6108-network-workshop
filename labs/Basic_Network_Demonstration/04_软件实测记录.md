# 软件实测记录

本记录区分软件运行结果与手册中的设计预期。已在本机 Cisco Packet Tracer 9.0.1 原生界面搭建 10 个设备、9 条连线，并保存 `PacketTracer` 中五个原生 `.pkt`：01 起始、02 VLAN、03 路由开放、04 ACL、05 单故障。01 保留默认设备名，尚未配置地址；不是完成答案。本记录反映已有技术验证，不证明学生学习效果，也不证明所有协议均可用。

表中 A、B 分别指 Student_A、Student_B；Server 指 HTTP_Server。ICMP 使用新建 PDU/Scenario 核对当前配置；HTTP/HTTPS 在 A 的 Desktop → Web Browser 中实际输入服务器 URL。本次只验收已列出的源、目的与协议；更换地址、端口或协议后应重新建立测试，不沿用原结论。

04 的原生配置已导出为 `configs/R1_acl_actual_export.txt`：核对五条 ACL 顺序为允许 TCP/80、允许 ICMP 到服务器、拒绝其他学生到服务器流量、拒绝学生到教师子网、允许其余 IP；绑定在 R1 `G0/0.10` 的 `in` 方向。导出的 `eq www` 对应 TCP 端口 80。严格对照时通过 File → Open 重新打开 03，A 的浏览器为空白页，输入 `https://10.61.8.100` 并点击 Go，约五秒后正确加载 EE6108 页面；04 同源、同目标的 HTTPS 显示 Request Timeout，HTTP 仍正确加载。此对照结合配置核查，支持本例 ACL 允许 TCP/80、拒绝服务器其他 IP 流量的解释。

05 仅把 SW_B `Fa0/1` 从 VLAN 10 改为 VLAN 20，Student_B 仍为 `10.61.8.11/26`；已保存 NVRAM 和 `.pkt`。04 中 A→B 成功提供正常基准；05 中 A→B 失败有截图，但尚未在该副本恢复端口并证明恢复成功。课堂修复应恢复 VLAN 10，再用新 PDU 复测。

旧 Scenario 中的 Failed 属于历史测试，不能代表修改后的网络仍失败。首次 ARP 导致的失败须等待并复测；持续失败还应检查端口、VLAN、掩码、网关、路由和服务，不能全部归因于 ARP。Teacher→Student、FTP 尚未实测；CRC 是纸面模型与数学核验，没有 Packet Tracer 位翻转或 TCP 自动重传的实测结论。
